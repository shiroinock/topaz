v0.2.0 is the first guidance-surface minor release after the
single-binary MVP and runtime TS prelude checkpoints.

## Changes

- Added capability/effect inference guidance for source graphs that import the
  current `std/*` modules, with public reporting through `topaz doctor <entry.ts>`.
- Added manifest generation guidance through `topaz manifest init <entry.ts>`
  and opt-in file creation through `topaz manifest init --write <entry.ts>`.
- Added `topaz check <entry.ts>` for entry-adjacent policy validation while
  keeping normal zero-config compile unchanged.
- Added discoverability commands for the guidance surface, including
  `topaz explain capability <name>`, `topaz explain capability fs.read`, and
  `topaz explain std/fs`.
- Preserved the existing artifact names, checksum format, runtime/prelude/header
  behavior, and single-binary compile path.

## Assets

- `topaz-darwin-arm64`: native Topaz compiler for Apple Silicon macOS.
- `SHA256SUMS`: checksum file for the compiler asset.

## Verification

After downloading the release assets into a temporary directory, verify the
checksum and guidance CLI surface:

```sh
shasum -a 256 -c SHA256SUMS
chmod +x ./topaz-darwin-arm64
./topaz-darwin-arm64 --help

mkdir -p guidance-smoke
cat > guidance-smoke/effectful.ts <<'EOF'
import { readFileSync, writeFileSync } from "std/fs";
import { writeStdout } from "std/process";

const text = readFileSync("guidance-smoke/input.txt", "utf8");
writeFileSync("guidance-smoke/out.txt", text);
writeStdout(text);
EOF
printf 'hello from guidance\n' > guidance-smoke/input.txt

./topaz-darwin-arm64 doctor guidance-smoke/effectful.ts
./topaz-darwin-arm64 manifest init guidance-smoke/effectful.ts
./topaz-darwin-arm64 manifest init --write guidance-smoke/effectful.ts
./topaz-darwin-arm64 check guidance-smoke/effectful.ts
./topaz-darwin-arm64 explain capability fs.read
./topaz-darwin-arm64 explain std/fs
```

Expected guidance observations:

- `doctor guidance-smoke/effectful.ts` reports `fs.read`, `fs.write`, and
  `io.stdout`.
- `manifest init guidance-smoke/effectful.ts` previews normalized policy text.
- `manifest init --write guidance-smoke/effectful.ts` creates the
  entry-adjacent `strict-ts.json` when it is absent.
- `check guidance-smoke/effectful.ts` reports `missing capabilities: none` and
  `status: ok`.
- `explain capability fs.read` describes the `fs.read` capability.
- `explain std/fs` describes the `std/fs` module.

## Notes

This release does not make `strict-ts.json` required for normal compilation:
zero-config compile remains unchanged. Capability diagnostics and manifest
guidance are available for planning and review, but compile-time policy enforcement,
runtime sandboxing, schema expansion, and richer policy discovery remain future
work. The compiler binary does not require Node.js, pnpm, or a checked-out
`runtime/` directory. It still invokes the platform C compiler (`cc`) when
producing native output.
