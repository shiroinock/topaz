## What this is

TypeScript-syntax AOT native compiler. TS の構文をフロントエンドにして、JS のセマンティクスを切り捨てた上で真の AOT ネイティブコンパイルを狙う。設計検討資料・ロードマップ・落とし穴は `MEMO.md`、Phase 0〜直近 Phase までの「なぜそう実装したか」の決定ログは `docs/archive/implementation-log.md`、Phase 0 のパーサ選定根拠は `docs/parser-choice.md`、Phase 1.5-2 着手前の self-hosting 棚卸しは `docs/archive/self-hosting-inventory.md` を参照。

## Commands

- `npm run build` — `tsc` で `src/` を `dist/` に出す。
- `npm test` — `tests/smoke.sh`。`examples/*.ts` を順にコンパイル→実行して期待値と一致するか確認する。新しいサンプルを追加したら `run_case` 行を増やす。
- `npm run topaz -- <input.ts> [-o out]` — CLI を npm 越しに起動。
- `node dist/cli.js <input.ts> [-o out] [--emit-c-only]` — 直接起動。`--emit-c-only` は cc を呼ばずに生成 C をファイルに残す。

cc のパスを変える / フラグ追加したい時は `src/cli.ts` の `execFileSync("cc", ...)` を直接編集。

## Architecture

パイプライン:

```
*.ts ──loader (DFS + cycle detect)──▶ ts.SourceFile[] ──codegen──▶ C source ──cc -O2 -Iruntime──▶ native binary
```

- `src/parser.ts` — `typescript` の `ts.createSourceFile` を呼ぶだけの薄いラッパ。型チェッカーは使わない(全プログラム推論は将来自前で書く)。
- `src/loader.ts` — Phase 1.5-2。root .ts から `import` を DFS で辿り、相対パス specifier (`./foo` / `../foo` / `.js` 拡張子は `.ts` に置換) のみを受け入れる。visiting set で循環検出、topological 順 (root が末尾) の `SourceFile[]` を返す。default import / namespace import / rename import / `import type` / `node:*` / bare specifier / 絶対パスはこの段で明示エラー(`LoaderError` で `file:line:col` 付き)。`codegen.ts` は import 文を読み飛ばし、全 module の宣言を単一 global namespace に flatten する。
- `src/codegen.ts` — AST から C を直接吐く。未対応構文は `CodegenError` で `file:line:col` 付きで投げて止まる(`MEMO §3.1` の「禁止じゃなく未対応」方針)。`emit(sourceFiles: readonly ts.SourceFile[])` で multi-module に対応(`Emitter` インスタンス 1 つで全 module の宣言・monomorph テーブルを共有)。`Emitter` クラスがレキシカルスコープ(`Scope`)、関数 signature テーブル(`functionSigs` = params + returnType)、generic function 宣言テーブル(`genericFunctions`)、generic monomorph キャッシュ(`genericMonomorphs`)、monomorph 出力 worklist(`genericWorklist`)、type param 解決スコープ(`typeParamScope`)、クラス情報テーブル(`classes`、generic class の monomorph は mangled name でここに登録される)、interface 情報テーブル(`interfaces`)、generic class 宣言テーブル(`genericClasses`)、generic class monomorph レジストリ(`classMonomorphs`)、generic class monomorph 出力 worklist(`classMonomorphWorklist`)、`this` の解決用に現在処理中のクラス名(`currentClass`)、`return` の coercion 用に現在処理中の関数 / メソッドの戻り値型(`currentReturnType`)を持ち、式単位で `inferType` を走らせて型不一致や `const` 再代入をエラーにする。型は `TopazType` = タグ付き union(`{ kind: "number" | "boolean" | "string" }` / `{ kind: "array", elem }` / `{ kind: "map", key, value }` / `{ kind: "set", elem }` / `{ kind: "class", name }` / `{ kind: "iface", name }`)で structured。`typeEq()` で structural 比較、`typeIdent()` で `topaz_array_class_Box__number` のような C 識別子へ折り畳む。型注釈なしの `let` / `const` は初期化式から型を推論する(`number` / `boolean` / `string` リテラル、識別子、関数呼び出し、各種演算、`new ClassName(...)`)。class → interface coercion は `emitWithExpected(expr, expectedType)` ヘルパに集約してあり、変数初期化 / 関数引数 / `return` / 代入 RHS の 4 サイトでのみ走る。
- `src/cli.ts` — argv パース、loader → codegen → cc を駆動。`runtime/` は `dist/../runtime` で解決。
- `runtime/runtime.h` — header-only。`topaz_number`(= `double`)、`topaz_boolean`(= C99 `bool`)、`topaz_string`(= `{ const char *data; size_t len; }`)、`topaz_console_log_*`、`topaz_fmod`、`topaz_string_concat`、`topaz_string_eq`、`topaz_number_to_string`(ECMA-262 shortest を arena 48-byte buf に書き出す、`console_log_number` 経由でも使われる)、`topaz_boolean_to_string`(`"true"` / `"false"` の static literal を `topaz_string` で返す、arena alloc 無し)、`TOPAZ_ARRAY_DEFINE(name, elem_t)` で monomorphize される growable array(`number` / `boolean` / `string` の 3 monomorph をプリ展開)、`topaz_hash_<scalar>` / `topaz_key_eq_<scalar>` / `topaz_hash_pointer`(reference identity 用ポインタハッシュ)と `TOPAZ_MAP_DEFINE(name, key_t, val_t, hash_fn, eq_fn)` / `TOPAZ_SET_DEFINE(name, elem_t, hash_fn, eq_fn)` で生成する open-addressing ハッシュテーブル(Map は scalar 3×3 の 9 monomorph、Set は 3 monomorph をプリ展開)。interface 用の fat pointer 型(`topaz_iface_<I> = { void *data; const struct topaz_iface_<I>_vt *vt; }`)と vtable struct、および class / interface 要素の `topaz_array_class_<C>` / `topaz_array_iface_<I>` / `topaz_map_<K>_class_<C>` / `topaz_map_<K>_iface_<I>` / `topaz_set_class_<C>` / `topaz_set_iface_<I>` monomorph は codegen 時にユーザー宣言から生成される(runtime.h 側に固有実装はない)。例外用に `topaz_try_frame`(= `{ jmp_buf env; struct topaz_try_frame *prev; }`)、frame stack の root `topaz_try_top`、payload global `topaz_throw_value`、`topaz_try_push` / `topaz_try_pop` / `topaz_throw` ヘルパも `static inline` で含む。

### 設計上の固定点

- **AST は tsc API**。Phase 1 以降 oxc に乗り換える条件は `docs/parser-choice.md` 参照。
- **C 出力 + 単一ヘッダランタイム**。LLVM IR は使わない(`MEMO §3.4`)。
- **型注釈は信用せずヒント扱い**(`MEMO §3.2`)。現状の codegen 内に式レベルの型推論が同居している。Phase 1.4c-3 で `TopazType` を string union → structured 表現に移行済み(`Array<Box<number>>` のようなネストが書ける)。本格的な全プログラム推論層を切り出すのは Phase 1.5 で全プログラム型検証を入れる時。
- **未対応構文はエラーで落とす**。`any` 禁止リンターは作らない。コンパイラが「多態」「構造的型の発散」を見つけた時点で諦める(`MEMO §3.1`)。
- **条件式は厳格 boolean**。`if` / `while` / `for` / `do-while` の条件は `boolean` を要求する(`if (n)` のような truthy / falsy は型エラー)。
- **緩い等価は未対応**。`==` / `!=` は `CodegenError` で「`===` / `!==` を使え」と教える(JS の値変換セマンティクスは持ち込まない)。
- **`let` / `const` は初期化必須、`var` は未対応**。`const` への再代入も `CodegenError`。
- **for-init は単一宣言まで**。`for (let i = 0, j = 0; ...)` は未対応(型が混じり得るため)。複数変数を回したい場合は外で宣言する。
- **`for-of` は `Array<T>` / `Set<T>` / `Map.values()` / `Map.keys()` / `Set.values()` / `Set.keys()` / `Map.entries()` / `Set.entries()` / `Iterator<T>`**(Phase 1.5-3.5b で Array、1.5-3.5g-mapset で Set / Map.values()/keys()、1.5-3.5g-iterator で `Iterator<T>` を追加、1.5-3.5h-entries で `.entries()` の destructuring 形を追加)。Array 経路は RHS を `topaz_array_<short> *` の tmp に snapshot してから index-based C for-loop に lower、body 先頭で `<elem> bindName = __arr->data[i];` を declare。Set / Map 経路(`emitForOfHashLowering` / hash-form)は RHS を `topaz_<map|set>_<...> *` の tmp に snapshot して `for (i = 0; i < ht->cap; i++) { if (slots[i].state != TOPAZ_HASH_SLOT_OCCUPIED) continue; <elem> bindName = slots[i].<key|value>; ... }` の cap-based walk + OCCUPIED skip に lower、`.entries()` 形は同 lowering を `bindSpec.kind === "pair"` で再パラメタライズして `<K> k = slots[i].key; <V> v = slots[i].value;` の 2 declaration を吐く(Set.entries() は両 binding が同じ `slots[i].key` を見る = JS の `[elem, elem]` semantics)。Iterator 経路(`emitForOfIteratorLowering` / while-form)は RHS を `topaz_iter_<T>` の tmp に snapshot して `for (;;) { bool __done = false; <T> __v = it.next(it.state, &__done); if (__done) break; <T> bindName = __v; ... }` に lower、`next` callback が EOF で `*done = true` を立てて zero 戻り値、caller は zero を捨てる。tombstone(`DELETED`)は state check で自然 skip、`cap == 0` の empty Map / Set は body に入らず safe、user の `continue` / `break` も同じ C ループに乗るので semantics が自然合成される。binding は `const` / `let` の単一識別子か `.entries()` 用の `[a, b]` pair destructuring のみ(`parseForOfBinding` が解析、ObjectBindingPattern・rest・default・property rename・nested pattern・omitted (sparse) elements・要素数 ≠ 2・pair binding への type annotation・初期化子付き・複数宣言・`var`・`for await` は明示エラー)。single binding の型注釈は elem 型と EXACT 一致を要求、pair binding は型注釈不可(両 element の C 型は RHS から確定するため)。**dispatch**: `emitForOfStatement` で `parseForOfBinding` を最初に呼んで binding kind を確定 → (1) `.values()` / `.keys()` + single → `emitForOfHashLowering(field)`(direct slot walk、Iterator の indirection を skip する性能パス)、(2) `.entries()` + pair → 新 hash-form pair path(K / V を同 slot から取り、Set 用は両方 `"key"` field を読む)、(3) `.entries()` + single → `for-of over .entries() requires destructuring binding` で reject、(4) RHS が `set` + single → `emitForOfHashLowering(field: "key")`、(5) RHS が `iter` + single → `emitForOfIteratorLowering`(while-form、bare iter binding 経由のみここに来る)、(6) RHS が `array` + single → 既存 `emitForOfArrayLowering`、(7) Array / Set / Iterator RHS + pair → `destructuring binding in for-of is only supported for .entries() on Map / Set` で reject。special form 判定は `inferType(rhs)` より先に行う(`.values()` の戻り値型を Iterator として持っていても direct walk の方が分岐が 1 段少ない)。**Map bare RHS** は引き続き reject(JS では `[K, V]` tuple yield、`.entries()` を使えと案内)、string RHS は `[i]` index 推奨、`for-in` は構文丸ごと未対応(prototype 探索が JS 固有のため)。**`.entries()` の bare 利用**(`const e = m.entries()` / `console.log(s.entries())` 等の for-of 外利用)は `Map.entries() is only allowed as the right-hand side of a for-of statement with destructuring binding` / 同 Set 版で reject、`emitMapMethodCall` / `emitSetMethodCall` / `inferType` の 3 箇所で同一 message。`Iterator<[K, V]>` の合成型は導入していない(現状の単一 `_next` callback signature では tuple 表現不可、tuple サポートとセットで別 step)。**iteration order**: Set / Map は insertion order ではなく hash 順(open-addressing slot 順)で yield する、JS 仕様の insertion-ordered とは divergence(documented divergence 入り、必要なら `OrderedMap<K, V>` を別 type で導入)。**ループ変数のライフタイム**: C ローカル変数は iteration ごとに再代入される(per-iteration 再 alloc しない)ため、1.5-3.5e で closure を入れた時に「ループ内で生成した arrow が全部最後の値を見る」状態になる。closure 着地時に再評価する宿題。
- **`Iterator<T>` は state + next 関数の fat pointer**(Phase 1.5-3.5g-iterator)。`Iterator<T>` 型注釈 → `{ kind: "iter", elem: T }`(TopazType)→ `topaz_iter_<elem-tag> = { void *state; T (*next)(void *state, bool *done); }`(C struct、1.5-3.5e の fn 値表現と同形)。**source**: 現状の生成器は `Map.values()` / `Map.keys()` / `Set.values()` / `Set.keys()` のみ(Set の両者は同じ `set_values` source に集約、JS で両者が elem を yield する semantics に揃える)。construction は `emitIterConstruction` が stmt-expression `({ topaz_iter_state_<C> *s = topaz_arena_alloc(sizeof(...)); s->src = recv; s->idx = 0; (topaz_iter_<T>){ .state = s, .next = (...)&topaz_iter_<C>_<values|keys>_next }; })` で arena 上に state を確保して fat pointer を組む。`recordIterMonomorph(elemType, containerType, source, field)` が 3 つの Map(`iterTypedefMonomorphs` / `iterStateMonomorphs` / `iterNextMonomorphs`)に登録、emit 末尾で per-elem typedef / per-container state struct / per-(source, container) `_next` 関数を 3 slot に drain(Map.values + Map.keys は state を共有、`_next` のみ独立 dedupe)。**slot 構成**: `iterTypedefSlot` = `containerMonomorphSlot` / `arrayJoinHelperSlot` の後・`fnTypedefSlot` の前(state struct が `topaz_map_<K>_<V> *` の typedef を必要とするため)。**`Iterator<T>` 型注釈**: `typeFromAnnotation` で 1 type argument 強制 + elem 形状チェック(scalar / class / iface のみ、Array / Map / Set / fn / union elem は reject)、bare 注釈だけでも typedef は emit slot に reserve(関数 return type で使われるため)。**container element 不可**: `elemTag` の `case "iter"` で明示 reject、`Array<Iterator<T>>` / `Map<scalar, Iterator<T>>` / `Set<Iterator<T>>` は全て reject(単一 pass + arena 上の可変 state を共有するため container ownership が不定、fn 値と同じ policy)。**iter 自身のメソッドは持たない**(`.map` / `.filter` / `.toArray()` 等は実装せず、必要なら for-of で書く)、`Symbol.iterator` の JS protocol も持ち込まない(Topaz 固有 type として扱う)、Array 系の lazy 化(`.map` を iter chain 化する設計)も着手しない、Array 系は引き続き eager。
- **`!` (non-null assertion) と `??` (nullish coalescing)** は `T | undefined` 専用(Phase 1.5-3.5c)。`!` は operand を tmp に snapshot して sentinel slot を check し、scalar は `topaz_opt_T` の `.present` を見て `.value` を取り出し、class は `T *` の NULL check、interface は fat pointer の `.data == NULL` check。失敗時は `fputs("topaz: non-null assertion failed\n", stderr); abort();`(JS の `TypeError` とは divergence、stack trace 無し)。`??` は同じ sentinel slot 上での short-circuit ternary に lower。**チェーン** `a ?? b ?? c` は中間結果を `T | undefined` のまま流し、最後の RHS が T になる時点で T を返す(scalar の場合は `.present ? __t : (b)` と `.present ? __t.value : (c)` を RHS 型に応じて切り替える)。RHS は `emitWithExpected` 経由で class → interface coercion と string-literal → string widening が自動。**no-op は明示エラー**: 既に `T` 型の値に対する `!` / `??` は assertion / fallback の意味が消えるため reject(TS は警告のみだが、Topaz は厳格に止める)。`!!`(double bang)/ `??=` (logical nullish assignment) は未対応(`??=` は assignment expression 全体の policy と合わせて再評価)。
- **arrow function + closure** は fat pointer fn 値(Phase 1.5-3.5e)。`(p: T) => R` の AST が `TopazType.fn` を生成、C 表現は `typedef struct topaz_fn_a<N>__<param>...__to__<ret> { <ret> (*fn)(void *env, <params>); void *env; } topaz_fn_a<N>__...` の fat pointer struct(arity prefix + `__to__` separator で mangling 一意)。arrow body は `__topaz_arrow_<N>` static C function に lower、capture がある時は `__topaz_env_<N>` env struct を `topaz_arena_alloc(sizeof(<env>))` で arena に確保して各 capture を field copy、呼び出しサイトは compound literal `((<fn type>){ .fn = (<fn ptr cast>)__topaz_arrow_<N>, .env = <env init or NULL> })`。**capture 戦略は by-value snapshot**: `Scope` の `pushBarrier` / `popBarrier` で arrow body の identifier lookup を outer フレームから遮断し、`collectCaptures` が body AST を walk して `isReferencePosition` filter(declaration site / property name / type ref / import specifier を除外) + `lookupAcrossBarrier` で free identifier を outer scope から拾う。ネスト arrow は inner の自由変数を transitive に outer の env に取り込む(inner の collectCaptures が outer の barrier 上で resolve するため)。body 内の identifier emit は `scope.lookup` がヒットすればローカル、外せば `captureContext.captures` を見て `(((<env type> *)__topaz_env)->name)` に rewrite。**call dispatch** は `emitCall` の identifier 分岐に fallback を入れ、`functionSigs` ヒット無しでも `inferType(callee).kind === "fn"` なら `emitFnValueCall` で `({ <fn type> __t = f; __t.fn(__t.env, args); })` (callee 単一評価) に lower。**contextual typing**: `emitWithExpected` が `expected: { kind: "fn" }` のときは `emitArrowFunction(arrow, expected)` を呼び、param annotation 無し arrow(`let f: (n: number) => number = (n) => n + 1`)を受理。expression body(`(n) => n + 1`)は `{ return <expr>; }` に lower、block body はそのまま emit。**for-of 内 arrow の per-iteration freshness** は env が iteration ごとに新規 arena alloc されるため自動(scalar capture は値コピー、reference capture は pointer コピーで同 object を共有)。**slot 構成**: `fnTypedefSlot`(container monomorph slot の後、user fn fwd の前)・`arrowFwdSlot`(user fn fwd の前)・`arrowDefSlot`(class monomorph def の後、generic mono def の前)、後 2 つは `-Wunused-parameter` で wrap(env が空の arrow も `void *__topaz_env` を持つため)。**未対応**(明示エラー): fn を `Array<T>` / `Map<scalar, V>` / `Set<T>` の要素 / 値に詰める(1.5-3.5f で `Array.map` 系を入れる時に container 側を解禁)、generic arrow / async arrow / `function () { ... }` expression(arrow を使えと案内)、nested fn 型(fn の param / return position に fn 型、mangling ambiguity)、`f?.()` optional call(1.5-3.5d で reject 済み、1.5-3.5e でも維持)、default / optional / rest / destructuring arrow パラメータ、class / interface field に fn 型を持つ。runtime.h は無修正(env 確保は `topaz_arena_alloc` を再利用、env 個別 free は不要 — arena 全体で OS 回収)。
- **`?.` (optional chaining)** は `T | undefined` receiver 専用(Phase 1.5-3.5d)。受理する形態は **`a?.b`(property access)・`a?.b()`(method call)・`a?.[i]`(element access、Array<U> 限定)** の 3 つで、result 型は常に `U | undefined`。lowering は共通の stmt-expression `({ <recv-c-type> __topaz_oc_<N> = <recv>; (<is-absent>) ? <absent> : <present>; })` で receiver を tmp に 1 回 snapshot して sentinel slot を check(scalar = `.present == false`、class = `T *` NULL、iface = fat pointer `.data == NULL`)、absent literal は既存 `emitUndefinedLiteral` を再利用(scalar = `topaz_opt_absent_<T>`、class = NULL ptr cast、iface = `{.data=NULL,.vt=NULL}` compound literal)、present branch は `applyCoercion(raw, U, U | undefined)` 経由で widening(scalar の場合は `topaz_opt_wrap_<T>` が自動で挟まる、class / iface は表現同一で no-op)。class field は `(${tmp})->${f}`、iface field は vtable getter `(${tmp}).vt->get_${f}((${tmp}).data)`、class method は `topaz_class_<C>_method_<m>(${tmp}, args)`、iface method は `(${tmp}).vt->${m}((${tmp}).data, args)`、array index は既存 bounds-check 付き `topaz_array_<name>_at(${tmp}, idx)`。**no-op `?.` は明示エラー**(non-optional receiver には short-circuit 意図が消える、`!` / `??` と同じ厳格化方針、TS は warning のみだが Topaz は止める)。**`f?.()` optional call は明示 reject**(function-valued binding の C 表現が arrow + closure 1.5-3.5e で確定するまで保留、エラーメッセージは `if (f !== undefined) f()` パターンへ誘導)。**`a?.b.c` の mixin** は `a?.b` の中間が `B | undefined` で続く plain `.c` の receiver が union 型になるため、既存の「cannot access '.c' on union type」エラーで自然に reject(`a?.b?.c` か `a?.b!.c` を書けと案内される)。runtime.h は無修正(全 lowering が既存の opt struct / class pointer / iface fat pointer / array `_at` accessor / vtable getter / method dispatch helper を再利用)。
- **`switch` は `do { ... } while (0)` への lowering**。case ラベルは判別式と同型のみ、`default` は最終 clause のみ、暗黙の fall-through は禁止(非空 case は `break` / `return` / `throw` / `continue` で終わる必要あり)、`switch` 本体内の `continue` は未対応(do/while(0) で吸われてしまうため、明示的にエラー)。switch の対応型は `number` / `boolean` / `string`(string は `topaz_string_eq` で比較)。
- **`string` は immutable・ASCII 限定**。`+` / `+=` で `topaz_string_concat`(arena 経由で alloc、プロセス終了で OS が一括回収、個別 free は無し)、`===` / `!==` は `topaz_string_eq`(byte 比較)、`.length` はバイト数(JS の UTF-16 code units とは divergence するため非 ASCII リテラルは codegen 段でエラー)。**template literal**(Phase 1.5-3.5a)は左結合の `topaz_string_concat` chain に lowering、各 `${}` substitution は `inferType` で number / boolean / string に絞った上で `topaz_number_to_string` / `topaz_boolean_to_string` / identity を挟む。空フラグメント(adjacent substitution の middle、pure-substitution の head/tail)は skip するので `` `${name}` `` のような単一埋め込みは concat 呼び出し 0 回まで折り畳まれる。class / interface / array / map / set / unnarrowed `T | undefined` の埋め込みは「template literal substitution must be number / boolean / string」で reject(`Map.get` の `V | undefined` も narrow しないとここで落ちる)。tagged template (`` tag`...` ``)、Unicode escape (`\u{1f600}`)、`.toString()` メソッド経由の format policy は未対応。

- **`ClassInfo.decl` の widening**: `ts.ClassDeclaration | ts.TypeLiteralNode` に変更(anon class の anchor を `TypeLiteralNode` で保持して `CodegenError` の `file:line:col` 表示を生かす)。anon class の field order は alphabetical sort 固定(declaration 順を保持しない、TS の構造的同型 semantics に揃える)。
- **class の未対応リスト(明示エラー)**。`extends`、`static` / `abstract` / `override` 修飾子(`public` / `private` / `protected` / `readonly` は 1.5-6 prep で no-op 受理に変更)、generic method(Phase 1.5 以降)、class expression、decorator、getter / setter、static block、parameter property shorthand(`constructor(public x: number)`)、`super`、メソッド参照(`obj.method` without `()`)、constructor 内 `return`、fn-typed field、class を `console.log` の引数に取る、`Map<ClassName, V>` で class を key にする方向(Map / Set / Array の値 / 要素方向は対応済み)。フィールド宣言は型注釈必須、初期化子(`x: T = init;`)は 1.5-6 prep で解禁(constructor body 冒頭への注入として lowering、auto-generated zero-arg ctor は全 field が initializer 持ちのときのみ)、partial init(一部だけ initializer で explicit ctor 無し)は引き続き reject。
- **interface は fat pointer + per-(I, C) vtable**。変数は `topaz_iface_<I>`(= `{ void *data; const struct topaz_iface_<I>_vt *vt; }`)を値として持ち、vtable には field ごとの `get_<f>` / `set_<f>` 関数ポインタとメソッド関数ポインタが並ぶ。class が複数の interface を implement する場合、per-(I, C) wrapper 関数 + static const vtable を 1 つずつ生成し、coercion 時に `((topaz_iface_<I>){ .data = obj, .vt = &topaz_iface_<I>_for_<C>_vt })` の compound literal で fat pointer を組み立てる。dispatch は `({ topaz_iface_<I> __t = base; __t.vt->method(__t.data, args); })` の GCC stmt expression で base を一度評価する形に統一(base が `makeShape(2)` のような副作用持ちでも二重評価を避けるため)。class→interface coercion は `emitWithExpected` ヘルパに集約し、変数初期化 / 関数引数 / `return` / 代入 RHS の 4 サイト + コンテナの `.push` / `.set` / `.add` 引数 / `[i] = v` の RHS で走る(interface→class narrowing、interface→interface coercion、`==` / `!==` での widening は未対応)。
- **interface の未対応リスト(明示エラー)**。`extends`(interface inheritance)、generic interface、optional field / method(`f?: T` / `m?(): T`)、interface modifiers(`export` / `default`)、`readonly` field、index signature(`[k: string]: T`)、call / construct signature、getter / setter、`new InterfaceName()`(implementing class を `new` しろと案内)、interface 値を `console.log` の引数に取る、interface field への compound assignment(`iface.f += v`、stmt expr で複雑化するため `iface.f = iface.f + v` を書けと案内)、interface field 代入の chain(`x = (iface.f = v)`、setter が void を返すため)、`Map<InterfaceName, V>` で interface を key にする方向。class が implement する際の構造的一致は EXACT match を要求(field / method 型が完全一致しないと「`class C.f` has type X, but interface I requires Y」)。
- **generic function は worklist monomorphize**。`function f<T, U>(...)` の宣言は `Emitter.genericFunctions` に登録され、signature 解決は遅延。呼び出しサイトで `resolveGenericCall` が (a) `f<number>(x)` のような explicit type args、または (b) 各 param TypeNode と引数 inferred type の構造マッチによる inference(`unifyTypeParam` が `T[]` / `Array<T>` / `Map<K, V>` / `Set<T>` / `Box<T>` のような generic class への type ref を decompose)を行い、mangled name(`f__number__string` 形式、`topaz_` prefix を剥がして `__` join)と substituted FunctionSig を作る。新規 monomorph は `genericMonomorphs` キャッシュ + `genericWorklist` に積まれ、`emit()` 末尾で worklist が空になるまで def を吐く(monomorph body から別の generic を呼んでも吸収できる)。`typeParamScope: Map<string, TopazType>` が monomorph body / type-arg 解決中だけ active で、`typeFromAnnotation` が `T` を class / interface より先に解決する(`class T {}` を宣言しても generic 関数の中では type param `T` が優先される)。fwd decl は user 関数 fwd の直後、def は user 関数 def の後・main の前、monomorph def 全体は `-Wunused-parameter` を ignore する pragma で囲む(`function pickSecond<A, B>(a: A, b: B): B { return b; }` のような片側 unused が普通にあるため)。
- **generic function の未対応リスト(明示エラー)**。type parameter constraint(`<T extends Shape>`)、default type parameter(`<T = number>`)、重複 type param 名(`<T, T>`)、type param への type argument(`T<U>`)、explicit type args の数不一致、inference 不能(全 type param が bind されないとき)、generic method / generic interface(Phase 1.5 以降)、`new` 経由の type args、型引数のみが違う関数 overload。inference は best-effort で、unify 失敗自体は黙ってスキップし、最後に「全 type param が bound されたか」だけを strict check する(本当の型不一致は call 後の `emitWithExpected` が param ごとに surface する)。
- **generic class も worklist monomorphize**。`class Box<T> { ... }` の宣言は `Emitter.genericClasses` に登録され、ClassInfo の構築は遅延。`new Box<number>(42)` / `Box<number>` の型注釈・`Array<Box<number>>` の inner type ref / generic function 経由の inference それぞれが `instantiateGenericClass` を経由し、`Box__number` のような mangled name(generic function と同じく `__` join)と substituted ClassInfo を作って `classes` / `classMonomorphs` に登録、`classMonomorphWorklist` に積む。recursive な型(`class Node<T> { next: Node<T>; }`)を吸収するため `ClassInfo` は `collectClassMembers` の前に pre-register する。monomorph 出力は 4 slot に分けて配置する: (a) `classMonoTypedefSlot` を全 concrete class struct の前に、(b) `classMonoStructSlot` を concrete struct 定義の後・interface vtable 定義の前に、(c) `classMonoSigSlot` を concrete 関数 sig fwd と並べて、(d) `classMonoDefSlot` は generic function def の前に、それぞれ `-Wunused-parameter` + `-Wunused-function` の pragma で囲んで吐く。member 関数の body emission 中は `typeParamScope = mono.subs` を再 active にしないと method body 内の `T` 型注釈が解決できないため、worklist drain ループで `subs` を保存・復元する。
- **generic class の未対応リスト(明示エラー)**。type parameter constraint(`<T extends Shape>`)、default type parameter(`<T = number>`)、重複 type param 名(`<T, T>`)、heritage clause(`extends` / `implements`、generic class は現状継承不可)、generic method(`class C { f<U>(...) {} }`、Phase 1.5 以降)、explicit type args の数不一致、inference 不能、generic interface(Phase 1.5 以降)。constructor 引数の型 / フィールド型 / メソッドの param と return type に type param を散らすところまでは対応(`replace(v: T): T` で `const old: T = this.value;` のような局所 `T` も解決する)。
- **例外は setjmp/longjmp + linked-list frame stack**。`throw expr` の `expr` は class instance に限定(`topaz_class_<C> *` を `void *` に詰めて `topaz_throw_value` に置き、top frame を pop して `longjmp(env, 1)`)。`try { ... } catch (e: ClassName) { ... }` は `{ topaz_try_frame f; topaz_try_push(&f); if (setjmp(f.env) == 0) { <body>; topaz_try_pop(); } else { topaz_class_<E> *e = (topaz_class_<E> *)topaz_throw_value; <catch>; } }` に lower。**Phase 1.5-3f**: catch binding の型注釈は optional 化。注釈無し (`catch (e)`) または `catch (e: unknown)` は `T_UNKNOWN` 型(C 表現は `void *e = topaz_throw_value;`)で受け、`if (e instanceof ClassName)` で narrow するまでは field / method 参照を reject。`catch (e: ClassName)` は引き続き受理(backwards-compatible)。frame stack の root は `topaz_try_top`(global、single-thread 前提なので `_Thread_local` ではない)、`topaz_throw` は longjmp 直前に **自分で frame を pop** する(catch body は frame-local state を触らず global の `topaz_throw_value` だけ読むので、setjmp 後の auto local の「indeterminate」問題を回避できる)。try body 末尾は明示的に `topaz_try_pop()`。nested try は frame stack に積み重なるだけで、inner で throw すると inner frame が pop されて inner catch に入る。uncaught(`topaz_try_top == NULL` で throw)は `topaz_throw` が `fputs("topaz: uncaught exception\n", stderr); abort();`(stack trace 無し、stack trace API は持たない)。
- **`instanceof` は class struct の RTTI tag 比較**(Phase 1.5-3f)。binary operator として追加、AST 上で左辺は `unknown` または class 型、右辺は宣言済み concrete class の識別子限定。lowering は `({ void *tmp = (void *)(<left>); tmp != NULL && *((const char * const *)tmp) == &topaz_class_<C>_tag; })` の stmt expression(NULL guard + 単一評価)。RTTI は全 class struct の先頭フィールド `const char *__topaz_class_tag` を constructor で per-class static sentinel のアドレスに初期化することで実現する。**`extractNarrowing`** は `<id> instanceof <Class>` の positive 分岐で id (unknown 型のみ) を当該 class に narrow、negative 分岐は他の class の可能性があるため narrow しない。narrow 後の identifier emit は `void *` → `(topaz_class_<C> *)<id>` に cast して field / method 経路に渡す。interface / dunion / generic class への narrowing は未対応(必要になった時に拡張)。
- **例外の未対応リスト(明示エラー)**。`finally` 句(Phase 1.5 残作業、cleanup と return / break / continue 解禁とセット)、catch binding 型が class / `unknown` 以外(interface / scalar / array / map / set)、catch の union 型受け(`catch (e: A | B)`、union 型自体が未対応)、throw 値が class instance 以外(primitive / interface / array)、bare `throw;`(rethrow 構文は持たない、明示的に `throw e;` を書く)、try body 内の `return` / `break` / `continue`(frame の `topaz_try_pop` を skip するので AST walk で reject、ネスト関数 / class / method 宣言の中までは降りない)、`Error.cause` chain / `new.target` / `Error.captureStackTrace` / stack trace API、`instanceof` の右辺が interface / generic class / 動的式(現状は宣言済み concrete class 識別子限定)。`unknown` narrowing が入ったので「catch で複数 class を扱いたい場合は `e: unknown` で受けて `if (e instanceof A) ... else if (e instanceof B) ...` で分岐」が標準パターン。
- **ES module は静的解決のみ・単一 global namespace に flatten**。`src/loader.ts` が root から `import` を DFS で辿り、相対パス specifier (`./foo` / `../foo` / `.js` 拡張子は `.ts` に置換、index 解決なし) のみを受ける。visiting set で循環検出して `circular import detected` で落とす。返す `SourceFile[]` は topological 順 (root が末尾) で、codegen は全 module の宣言を単一 global namespace に flatten する。`import { a, b } from "./x.js"` と side-effect `import "./x.js"` のみ受ける(import で取り込んだ名前は global なので、codegen は import 文を読み飛ばすだけで identifier 解決は通常の scope lookup で済む)。`export class` / `export function` / `export interface` 修飾子は受理(意味は no-op、可視性は 1.5-3 の全プログラム型検証で再評価)。**root 1 ファイルの top-level statement のみが `main()` body に入る**(非 root module の `let` / `const` / 式文 / 制御フローは明示エラー)。生成 C は引き続き単一 TU(`runtime.h` を include して全宣言を flat に並べ、`int main(void) { ... }` で root を実行)。
- **ES module の未対応リスト(明示エラー)**。`node:*` / npm bare specifier / 絶対パス module(parser 戦略 1.5-6 まで保留)、default import (`import X from "..."`)、namespace import (`import * as ns from "..."`)、rename import (`import { a as b } from "..."`)、`import type` / type-only import specifier、`export default`、named re-export (`export { a, b }`)、`export * from "..."`、index ディレクトリ解決 / `package.json` の `exports`、dynamic `import()`、module-level の strict visibility(`export` 無し宣言を他 module から参照不可にする、1.5-3 で再評価)、非 root module の top-level executable statement(`let` / `const` / 式文 / 制御フロー、1.5-4 で module init 設計時に再評価)。

### 既知の divergence

- `string.length` は UTF-8 バイト長で、JS の UTF-16 code units と divergence する。非 ASCII を含む文字列リテラルは codegen 段でエラーに落としているため未対応のまま顕在化はしないが、`Array` や FFI で外から非 ASCII が来た時点で破綻する。Phase 1.5(全プログラム型検証)で UTF-16 へ寄せるか、`string` を UCS-2 / UTF-16 で表現し直すか決める。
- `topaz_number_to_string` は `snprintf("%.*e") + strtod` のラウンドトリップ探索を 1〜17 回まわす実装で、観測上の出力は ECMA-262 ToString と一致するが、Ryu と比べて 1〜2 桁遅い。Phase 2 のベンチマーク整備時に Ryu(Ulf Adams)へ差し替える宿題。1.5-3.5a で `console_log_number` も `topaz_number_to_string` 経由に統一したので、`console.log(n)` も毎回 arena に 24-48 bytes 焼くようになった(template literal の arena コストに比べて誤差レベルなので問題視せず)。
- ヒープ管理は per-process arena(Phase 1.5-4)。string concat / class instance / Array `data` / Map `slots` / Set `slots` の全 alloc が `runtime/runtime.h` 先頭の bump allocator (`topaz_arena_alloc` / `_calloc` / `_realloc`)に乗る。`free` は no-op、プロセス終了で OS が arena chunk を一括回収する。**peak memory への影響**: realloc は単純な alloc + memcpy で古い buffer は捨てる(in-place 拡張なし)ため、Array doubling / Map rehash 中の一時的な peak は 2× まで膨らみうる(amortized は O(1) のまま)。長時間走らせる用途(REPL / interpreter)では reset 機構が必要だが、コンパイラは「1 プロセス = 1 コンパイル」なので未対応のまま。詳細は `docs/archive/implementation-log.md` の Phase 1.5-4 決定ログ。
- `Map.get(k)` は `V | undefined` を返す。scalar V は `topaz_opt_<scalar>` の sentinel struct(`{ present: bool, value: T }`)に lower、class V は `T *`(NULL = undefined)、interface V は `topaz_iface_<I>`(`.data == NULL` = undefined)。narrowing 必須で、bare read は型エラー(`if (x !== undefined)` の中だけで `x` が `V` として通る)。`Map.set` / `Set.add` は JS では `this` を返すが、`Array.push` と同じく void 扱いで chain 不可。
- class インスタンスはすべて `topaz_arena_calloc(1, sizeof(*self))` で確保するため、JS の「未初期化フィールドは `undefined`」とは divergence する。scalar field は 0 / false / `{NULL, 0}` の空 string で、reference field は NULL ポインタになる。constructor 内で全フィールドに代入することを実装者が責任を持つ前提だが、Phase 1.5-3a で `verifyDefiniteFieldInit` が ctor body の top-level 代入を集めて未初期化 field をコンパイル時 reject する(制御フロー内の代入は 1.5-3a の保守実装では「無代入」扱い、1.5-3d 以降の flow-sensitive 版で詰める宿題)。
- interface は EXACT 構造的一致を要求する(covariant return / contravariant param なし)ため、TS の構造的サブタイプとは divergence する。例えば interface が `f(): I` で、class が `f(): C`(C implements I)を返すケースは「class C.f returns C, but interface I requires I」エラーになる。Phase 1.4c の generics で variance を持ち込むかどうか判断する宿題。interface field 代入(`iface.f = v`)は vtable setter 経由で void を返すため、`x = (iface.f = v)` の chained assignment は使えない(C 側で「assigning void to ...」のコンパイルエラーになる)。class field 代入は C lvalue なので chain できる、その差は documentation で許容。
- 例外は throw 値が class instance に限定されるため、JS / TS が許す任意値(`throw 42` / `throw "boom"` / `throw {}`)とは divergence。catch binding は注釈無し / `catch (e: unknown)` / `catch (e: ClassName)` のいずれかを受理(Phase 1.5-3f で `unknown` narrowing が入ったので注釈無しでも `instanceof` 経由で使える)。`instanceof` は左辺が class instance または `unknown`、右辺が宣言済み concrete class 識別子に限定(interface / generic class / 動的式は未対応)で TS のフル仕様とは divergence。`finally` 句および try body 内の `return` / `break` / `continue` も未対応で、`finally` がない仕様なので「成功・失敗を問わず実行する cleanup」は呼び出し側で書く必要がある。uncaught exception は `topaz_class_<C> *` の中身(`.msg` 等のフィールド)を表示せず `topaz: uncaught exception` + `abort` で SIGABRT、stack trace も無い(JS の console.error + 非 0 終了とは divergence、core dump / debugger trap で原因を追える前提)。throw した class instance は arena に乗っているため、`abort` 前に明示的な解放は不要(OS が回収する)。

## 残タスク

ロードマップ全体は `MEMO §6`。直近の次フェーズは:

- **Phase 1.5 の残り** — syntactic sugar 集中投入の続き(1.5-3.5g-array-fn = `Array<fn>` storage、destructuring / spread、`.entries()` 解禁は destructuring とセット)、generic method / generic interface、self-hosting 通過。1.5-6 prep(self-hosting 地ならし)として access modifier no-op 受理 + void 戻り値型解禁 + field initializer 解禁 + type alias + **object literal type / expression(anonymous class lowering)** が全 5 ステップ着地済み(残無し)。全プログラム型検証(多態検出 / discriminated union narrowing / catch `unknown` narrowing / `T | undefined` narrowing / `Map.get` の `V | undefined` / `--strictPropertyInitialization` 相当)とヒープ管理(per-process arena)はそれぞれ 1.5-3a〜f / 1.5-4 で着地済み、template literal は 1.5-3.5a、`for-of over Array<T>` は 1.5-3.5b、`!` / `??` は 1.5-3.5c、optional chaining は 1.5-3.5d、arrow + closure は 1.5-3.5e、Array higher-order メソッド 5 種(map / filter / includes / slice / join)は 1.5-3.5f、`for-of over Set / Map.values() / Map.keys()` は 1.5-3.5g-mapset、`Iterator<T>` を first-class 型として昇格(bare `.values()` / `.keys()` 解禁 + for-of 5 経路目)は 1.5-3.5g-iterator で着地。値型コンテナ(自前 Box / List etc.)を書けるようになったので、Set の構造的等値の必要性もここで再評価する。`finally` 句および try body 内の `return` / `break` / `continue` 解禁は cleanup の lowering とセットでこの中で再着手する。

順序はあくまで現時点の見立てで、self-hosting に必要な機能から逆算して入れ替える。新機能を入れる時は **「コンパイラが自分自身をコンパイルできる範囲」がサブセットの下限**(`MEMO §3.3`)であることを忘れない。新しい Phase を着地させた時の決定ログは `docs/archive/implementation-log.md` の末尾に追記する運用。
